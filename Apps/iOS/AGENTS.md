# SwiftUI app

- iOS 26 minimum with Liquid Glass. Use system materials and controls before custom ones. Duo arrangements, reserved regions and toolbar axis behavior require iOS 27.1; isolate them with availability guards while retaining the iOS 26 ordinary-iPhone layout. This is the justified exception to the root no-fallback rule (MOV-62).
- **Observation:** `@Observable` models marked `@MainActor`. The owner holds them in `@State`; children get them via `@Environment` or plain properties, with `@Bindable` only for two-way bindings. Don't use `ObservableObject`, `@Published`, `@StateObject` or `@EnvironmentObject`.
- **Views** stay small and logic-free: extract a subview past about 50 lines. Use `.task`/`.task(id:)` for async work, `NavigationStack` with typed routes, `.foregroundStyle`.
- **Rendering** goes through `RenderService` (an actor); never render on the main actor. Inject dependencies through `@Environment` or initializers, not new singletons.
- **Regular iPhone and iPhone Duo are equal priority.** Build both properly; neither is an afterthought (MOV-119).
  - On Duo unfolded, use the whole landscape canvas with its own layout. Never a stretched phone UI. Examples: the photo large plus a persistent control panel, a grid plus a big preview, before/after across the fold.
  - Respect reserved regions (fold, camera) and use `ArrangementView` / adaptive layout APIs, not the hinge angle. Keep state when folding mid-edit.
  - Every UI PR shows proof on the iPhone 17 Pro simulator and the iPhone Duo simulator (folded and unfolded). That needs the Xcode 27.1 SDK.
- **Screen idiom (MOV-54/55/56):** the camera is the root screen (MOV-60/121): neutral black, the viewfinder aspect-fit, shutter controls below it in portrait and in a trailing rail when wide; the compact lens picker floats on the viewfinder; the recipe strip lies over the viewfinder's bottom edge on demand and is always visible on Duo unfolded; frames go straight to a layer, never through SwiftUI state. The library is an edge-to-edge grid under system toolbars, following the system appearance. The editor is a neutral black, white-tinted workspace; the photo stays aspect-fit, without decorative overlays; the title says "Original" while comparing. Keep edit state, the selected adjustment and the library preview above layout branches so folding, hiding and rotation keep them.
  - Compact (iPhone, Duo folded): Adjust reveals one Photos-style ruler on a glass panel; hidden by default.
  - Expanded (a division region, active or not, or regular width and height; iOS 27.1): system split arrangements. Library: a 4-column grid beside a preview pane (photo, date, RAW/Edited, Edit Photo). Editor: photo beside a single vertical ruler where it fits, or the glass inspector for large text and short layouts, shown by default; an explicit Adjust tap overrides the default in both postures. Hiding drops the split's axes so the photo view isn't rebuilt; `RenderService.latestRender` covers rebuilds across fold/unfold.
  - Duo vertical editor prototype: use one scrub ruler next to the photo when a division region exists or the system toolbar is vertical. Scrub up to increase the value, and use the picker above it to switch adjustments. Short layouts and accessibility text sizes keep the existing panel or inspector so labels fit.
  - Quick Looks opens a transient glass tray at the bottom on compact iPhone, or at the side where Duo provides vertical controls. Render swatches at thumbnail size through the existing cache. Tapping a swatch applies it immediately and keeps the tray open. A tap on the photo outside the tray dismisses it.
  - Active division/occlusion regions displace the image into a contiguous usable rectangle; system navigation owns vertical bars. Never infer a model from device dimensions. Keep native fold and occlusion coverage current (MOV-62/63).
- **Accessibility:** every control has a label and supports Dynamic Type.
- Folders are organized by feature (`Camera/`, `Library/`, `Editor/`), with helpers used by several features in `Shared/`. Models and app logic live in `Packages/EmulsionKit`, not in the app.
- Launch arguments and accessibility identifiers live in `Shared/LaunchArgument.swift` and `Shared/AccessibilityID.swift`; `EmulsionUITests/` mirrors them in files of the same names. Change both together.
- **Run it before every app PR.** Build, then run the UI walkthrough on a fresh install. The camera walkthrough runs on the Simulator's stand-in camera (the sample photos as a live viewfinder); the library walkthrough launches with `--library`. It adds the sample photos, edits, compares, rotates and saves to Photos, and keeps screenshots in the result bundle for the PR Proof:
  ```bash
  xcrun simctl uninstall booted com.hammad.emulsion; rm -rf /tmp/ui.xcresult /tmp/ui-shots
  xcodebuild test -project Apps/iOS/Emulsion.xcodeproj -scheme Emulsion -destination 'platform=iOS Simulator,name=iPhone 17 Pro,OS=26.2' -resultBundlePath /tmp/ui.xcresult
  xcrun xcresulttool export attachments --path /tmp/ui.xcresult --output-path /tmp/ui-shots
  ```
  The walkthrough covers the phone layout only; it cannot select a Duo pose. Set Duo poses with T3 `agent-device fold closed|half-open|open` or Xcode Device Hub's Closed / Partially Open / Open buttons, on a simulator of your own with your own bundle ID. Capture the inner display with `xcrun simctl io <udid> screenshot --display primary-1`. Record which tool and pose each proof capture used, and say so when a pose could not be verified; never fake a pose with generic UI clicks or simctl taps.
  The bundled samples aren't RAW, so `WhiteBalanceUITests` is skipped unless the app's library has a RAW photo: launch the isolated proof app once with `--library`, copy a synthetic DNG (`RAWDevelopChart.dng`, named `<UUID>.dng`) into its `Library/Application Support/Emulsion/` folder, then run the test. Never use a real photo for this.
  Launch with `--viewfinder-timing` (debug builds) to show the viewfinder's frame time and rate.
  Launch with `-camera-scenario <name>` (debug Simulator builds) to show a camera state the Simulator can't produce: `in-use`, `multitasking`, `overheated`, `critical`, `failed`, `denied`, `restricted` (`CameraScenario.swift`).

## Notes
- **Expanded canvas** (`isExpandedCanvas`): a division region, flat or not, or regular width and height. Regular width alone isn't enough: a large iPhone in landscape is regular-width but too short for the split. Always false before iOS 27.1. Toolbar titles show beside icons in horizontal bars only; vertical bars keep the icon-only default, where a title would crowd the column.
- **Camera:** controls stop growing at `FilmLabLayout.largestCameraTextSize` (accessibility1), like the system Camera, so the viewfinder keeps its room; long-press shows each label large, and the recipe button hides its name at accessibility sizes. The landscape rail lays everything but the shutter across it to fit a phone's landscape height (about 350 pt inside the margins on iPhone 17 Pro) and scrolls at accessibility sizes. The recipe button has a fixed width so switching recipes never moves it; with `toggle` nil (strip always shown) it only names the recipe. The strip's selection is a snapshot: a deleted recipe has no chip selected. Frames start portrait 3:4 until the first one arrives; frames are capped at 1920 px. A pause blurs the frozen viewfinder and says why, like the system Camera, rather than an alert (MOV-133); `-camera-scenario` events arrive 2 s after start so frames show first. The camera screen forces dark appearance on itself only, so the library above keeps the system appearance.
- **Library:** thumbnail labels include the time to tell apart photos taken the same day, and picked thumbnails get a light wash, as Photos does. The empty state's Import uses `.tint(.primary)` with an inverted foreground (about 19:1): white on the system blue failed the contrast audit (MOV-59), and `.background` as the label style renders invisible in dark mode.
- **Editor:** stacked, the photo keeps at least half the height and the panel scrolls at accessibility sizes; beside the photo the panel is 360 pt wide for ruler travel, and the expanded inspector 320–360 pt.
- **UI tests:** on a folded iPhone Duo the contrast audit failed text measuring about 20:1 or threw "Invalid target app" (MOV-140), so `audit` drops contrast when folded (folded contrast stays unverified; a contrast-only audit skips). Screenshots keep whichever Duo screen is lit. `keepProof` attaches each labelled element's role, label, value and state in reading order. Text clipping on the camera is audited with the recipe strip hidden; unfolded it is always shown. The expanded canvas shows its adjustment controls by default.
